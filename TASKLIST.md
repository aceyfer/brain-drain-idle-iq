- Push/local notification system (captured 2026-08-06, design settled 2026-08-06, NOT scoped, NOT approved for code): the project currently has NO notification system at all. `Assets/Plans/integration-vfx-music.md:85` shows local notifications were deliberately skipped because DataBite Plankton's remote FCM was assumed available — Plankton was removed in c567a7c as an ad SDK, so that assumption is void and the plan is stale. For an idle game this is a real retention lever. DESIGN NOW SETTLED, the following are decisions not options: (a) THRESHOLD IS PLAYER-SET. The player picks the level at which they are notified, via a slider in settings. Because the player chose it themselves, the system cannot feel like nagging — this is the core insight and should not be traded away. Reference: HP-flash threshold settings in RPGs such as MapleStory. (b) THE SLIDER IS EXPRESSED AS A PERCENTAGE OF BRAIN FUNCTION, NOT AS A RAW IQ NUMBER. Two reasons. Thematically, the "humans only use 10% of their brain" claim is a famous and completely false piece of pop-science, so a game satirising stupidity measuring intelligence in a unit that is itself stupid is on-premise, and COGS would use a debunked metric with total bureaucratic confidence. Architecturally, percentage DECOUPLES the settings UI from the IQ constants, so a later IQ rebalance cannot break the slider or introduce an out-of-range clamp bug. Use a slider, not a numberpad — a slider cannot produce an out-of-range value. (c) SCHEDULE-ON-CLOSE, NEVER POLL. Android local notifications are scheduled, not polled, so nothing runs in the background and nothing watches IQ. On `OnApplicationPause` the game branches ONCE: if IQ is above the player's threshold, compute the crossing time from the existing decay rate and schedule one notification for that moment; if IQ is already at floor, skip the math entirely and schedule a long-absence line at a fixed delay instead. That is one `if` and two possible schedules. It only READS the decay rate and adds no new economy math, so it does not touch the balance structure. Side effect worth keeping: a player who never backgrounds the app never gets notified, so the system is self-silencing. (d) FLOOR OVERRIDE per Aceyfer: a player parked at the floor longer than normal should still get a notification — this is the second branch in (c) and is already covered. (e) COPY IS REVERSE PSYCHOLOGY, NEVER A NAG. COGS is relieved the player stopped and actively discourages their return, which pulls a lapsed player back out of spite. 30 lines (25 standard + 5 long-absence) were written by Grok on 2026-08-06 and are LOCKED — do not rewrite, soften or "improve" them. They live in this session's transcript and must be transferred into the repo before that transcript ages out. (f) TITLE/BODY SPLIT REQUIRED. Audit finding: all 30 lines clear the 110-character cap (range 78-101, median 90) but ALL 30 exceed roughly 65 characters, which is where Android collapses a notification body to one truncated line. Every line is built as two sentences where the SECOND carries the payload, so naive single-field display truncates the punchline and destroys the joke. Fix requires zero copy changes: split each line at its existing period, sentence one becomes the notification title, sentence two becomes the body. This reads better than the original because the title lands like a file header stamped on the player. (g) Settings gear uses COGS cog iconography; the on/off toggle is MANDATORY, not optional polish.
